# v2.3.1 验证范围

本说明区分自动化测试、合成数据桌面操作和维护者手工确认。验证完成日期：2026-10-24。截图均来自合成数据，没有公开个人账本。

## 自动化检查

本轮交付及提交前运行：

- 前端：9个测试文件、62项测试，覆盖金额与数量、导入导出、回款、结算核对、售后引用、本地存储错误和页面渲染。
- Rust：14项库测试，覆盖SQLite迁移1–6、分单位金额、库存事务、图片写入、完整备份恢复、历史回款迁移及结算核对回滚。
- TypeScript类型检查、Vite生产构建、版本一致性检查和git diff空白检查。
- Windows x64 Release主程序与NSIS安装包构建成功。

运行方式见 [README](../README.md#检查与构建)。前端中的SQLite路径测试使用桥接模拟；真实SQLite迁移和事务另由Rust库测试与独立原生验收覆盖。

## 合成数据原生桌面验收

使用独立应用标识、SQLite和WebView数据目录的同源调试构建，前端资源与正式Release使用的dist逐文件SHA256一致。没有将浏览器LocalStorage验收当作真实SQLite验收。

- 检查800×600与最大化窗口、蓝白主题、分组导航和独立回收站入口。
- 通过Windows原生「打开」对话框恢复完整JSON v4合成备份：9条商品（8条有效、1条回收站）、2个分类、1个费用模板、2条库存流水及资金 / 售后集合。
- 通过原生「另存为」对话框导出JSON，与输入的商品、图片映射、分类、模板、库存流水和资金集合逐项对比一致。
- 通过原生「另存为」对话框导出CSV和Excel：各8条有效记录，检查中文表头、记录ID及Excel工作簿结构。
- 关闭并重开后，6张SQLite表内容一致，首页汇总和回收站数量保留；历史记录没有被补填到账日期或金额。
- 其他阶段另检查了保存失败保留输入、脏表单、确认框焦点、窄屏和既有外观偏好。

## 正式安装后的手工确认

维护者自行安装2.3.1，并手动选择蓝白主题。随后反馈原有商品、库存与回收站、回款状态和金额、重启后的数据与外观均正常。该结果是本机手工确认，不代表覆盖其他Windows设备或所有历史数据库。

## 明确未覆盖的范围

- 没有做多设备、全Windows版本或所有历史账本的兼容性认证。
- 本轮原生界面没有重复验证CSV / Excel导入；已验证其解析逻辑和原生导出。
- 本轮合成备份没有商品图片，只验证了空图片映射；带图状态由既有自动化测试覆盖，不能据此声称真实图片账本已完整恢复验收。
- 没有做数字签名或自动更新服务的验证。
- 仓库推送不等于GitHub Release发布。在线CI的结果以对应提交的Actions页面为准。
